# **Введение** 

В современном программировании разработка программного обеспечения редко обходится без систем контроля версий (Version Control Systems). Они позволяют фиксировать историю изменений кода, возвращаться к предыдущим версиям, а также безопасно работать над проектом в команде. 

Одной из самых популярных и мощных систем контроля версий является Git — распределенная система, которая хранит историю локально на компьютере. Для удаленного хранения кода, резервного копирования и совместной работы используется веб-сервис GitHub. 

Цель работы: Изучить базовые концепции контроля версий, приобрести практические навыки установки и настройки Git, создания локальных и удаленных репозиториев, а также организации правильной структуры каталогов для хранения последующих лабораторных работ по программированию. 


# **Ход работы** 

Выполнение работы состояло из нескольких последовательных этапов. 1.Установка и глобальная настройка Git на персональный компьютер был установлен дистрибутив Git с официального сайта. Проверка корректности установки и версии программы осуществлялась в терминале с помощью команды git--version. Перед началом работы была выполнена глобальная настройка Git. Это критически важный этап, так как система должна знать, кому приписывать те или иные изменения. С помощью команд git config -- global user.name "Имя" и git config --global user.email "email@example.com" были заданы данные пользователя, которые впоследствии будут прикрепляться к каждому коммиту (сохранению). 

2. Создание локального репозитория на жестком диске была создана единая корневая папка labs, внутри которой планируется хранить все лабораторные работы по текущей дисциплине. Перейдя в эту папку через терминал, была выполнена команда git init. Эта команда инициализировала репозиторий — внутри папки создалась скрытая директория .git, в которой Git начал отслеживать все изменения. 

3. Формирование структуры проекта для упорядочивания данных внутри корневой папки были созданы каталоги для каждой лабораторной работы (например, LR_1, LR_2, LR_4). В эти папки были добавлены файлы отчетов в формате Markdown (.md).С помощью команды git status был проверен статус репозитория: Git корректно определил новые, еще не отслеживаемые файлы (они подсвечиваются красным цветом). 

4. Фиксация изменений (Коммит). Для сохранения состояния проекта использовалась последовательность из двух команд. Сначала команда git add . добавила все новые файлы и папки в специальную область подготовленных изменений (индекс). Затем с помощью команды git commit -m "Добавлены отчеты" был создан первый снимок (коммит) проекта с осмысленным комментарием. На данном этапе изменения были сохранены только локально на компьютере. 

5. Создание удаленного репозитория на GitHub и связывание На платформе GitHub был создан новый публичный репозиторий с названием lab_3 (без инициализации README и .gitignore, так как локальный код уже существовал). Для связи локального репозитория с удаленным была использована команда git remote add origin https://github.com/..., которая создала псевдоним origin для ссылки на сервер GitHub. 

6. Отправка данных на удаленный сервер - современный стандарт GitHub подразумевает использование главной ветки с именем main. С помощью команды git branch -M main локальная ветка была переименована. Финальным этапом стала отправка всех сохраненных коммитов на сервер.
